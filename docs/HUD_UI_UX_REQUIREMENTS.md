# Even G2 HUD UI/UX要件

## 1. 目的

本画面の目的は、ユーザーが鉄道乗車中に短い視線移動だけで、以下を把握できるようにすることである。

1. 何線、またはどの列車に乗っているか
2. どの駅間を走行しているか
3. 現在どれくらいの速度で走行しているか
4. 表示値がGPS観測値か推定値か
5. 次駅までどの程度進んでいるか

本画面はスマートフォン画面ではなく、Even G2のHUD表示専用に設計する。

---

# 2. ディスプレイ条件

論理画面サイズを次に固定する。

```text
Width: 576px
Height: 288px
Color: green monochrome, 16 levels
```

ルート要素には次を設定する。

```css
.hud-root {
  position: relative;
  width: 576px;
  height: 288px;
  overflow: hidden;
}
```

レスポンシブ縮小、縦スクロール、横スクロールを使用してはならない。

ブラウザの表示領域に合わせて自動的に縮小するのではなく、576×288pxを基準として描画すること。

---

# 3. HUD特有の設計原則

Even G2では、ユーザーが長時間画面を凝視することを前提としない。

以下を優先する。

* 一瞥で認識できる
* 視線移動が少ない
* 細い線を使わない
* 小さい文字を使わない
* 情報の位置が変わらない
* 表示内容が頻繁に点滅しない
* 速度の桁数が変わっても横位置が揺れない
* 推定状態でも速度表示を突然消さない
* 不確実な情報を断定表示しない

常用画面では、ユーザーが読む必要のある情報ブロックを最大4個に制限する。

---

# 4. 安全領域

画面外周は、光学的な見切れや視線移動によって読みづらくなる可能性があるため、重要情報を配置しない。

```ts
const HUD_SAFE_AREA = {
  left: 24,
  right: 24,
  top: 12,
  bottom: 16,
};
```

重要情報を配置できる範囲は次とする。

```text
X: 24〜552
Y: 12〜272
```

以下は安全領域外へ配置しない。

* 速度
* 路線名
* 駅名
* GPS／DR状態
* 列車番号
* 次駅までの距離

---

# 5. 常用画面の固定レイアウト

常用画面は以下の4領域で構成する。

```text
┌────────────────────────────────────────────────────┐
│ HEADER                                             │
├────────────────────────────────────────────────────┤
│                                                    │
│                  SPEED                             │
│                                                    │
├────────────────────────────────────────────────────┤
│ SEGMENT                                            │
├────────────────────────────────────────────────────┤
│ FOOTER                                             │
└────────────────────────────────────────────────────┘
```

各領域の座標を次に固定する。

```ts
const HUD_LAYOUT = {
  header: {
    x: 24,
    y: 12,
    width: 528,
    height: 34,
  },

  speed: {
    x: 24,
    y: 50,
    width: 528,
    height: 110,
  },

  segment: {
    x: 24,
    y: 168,
    width: 528,
    height: 70,
  },

  footer: {
    x: 24,
    y: 244,
    width: 528,
    height: 28,
  },
};
```

各状態で領域の位置を変更してはならない。

表示状態によって要素を入れ替える場合も、同じ領域内で行う。

---

# 6. 輝度階層

緑16階調をすべて情報表現に使用してはならない。

原則として以下の4段階だけを使用する。

```ts
const HUD_BRIGHTNESS = {
  primary: 15,
  secondary: 11,
  tertiary: 7,
  disabled: 4,
  background: 0,
};
```

用途は以下とする。

## Primary: 15

* 現在速度
* 次駅名
* 現在駅名
* 重要な警告

## Secondary: 11

* 路線名
* 前駅名
* 種別
* 行先
* 区間進捗バー

## Tertiary: 7

* 単位
* 次駅までの距離
* 列車番号
* 区間最高速度
* GPS／DR状態

## Disabled: 4

* 未確定候補
* 読み込み中
* 無効な進捗バー
* 低信頼情報

アンチエイリアスによる中間階調が発生してもよいが、情報の意味を中間階調だけに依存させてはならない。

---

# 7. フォント要件

常用画面では18px未満の文字を使用してはならない。

```ts
const HUD_FONT_SIZE = {
  speed: 104,
  speedUnit: 24,
  estimatedMark: 28,

  lineName: 24,
  service: 20,

  station: 24,
  secondaryInfo: 18,
  footer: 18,
};
```

文字の太さは以下を推奨する。

```text
速度: Bold
駅名: Semibold
路線名: Semibold
補助情報: Medium
```

Light、Thin、100、200相当の細いフォントウェイトを使用してはならない。

数字には等幅数字を使用する。

```css
.speed-value {
  font-variant-numeric: tabular-nums;
  font-feature-settings: "tnum";
}
```

速度の桁数が変化しても、数字全体の中心位置が移動しないようにする。

# 8. HEADER領域

座標：

```text
X: 24
Y: 12
Width: 528
Height: 34
```

HEADERを左右2領域に分ける。

```ts
const HEADER_LAYOUT = {
  lineName: {
    x: 24,
    width: 300,
  },

  service: {
    x: 332,
    width: 220,
  },
};
```

## 左側

表示優先順位：

1. 路線名
2. 事業者略称＋路線名
3. 路線特定中

例：

```text
小田急小田原線
JR東海道本線
東京メトロ東西線
路線特定中
```

文字サイズ：

```text
標準: 24px
縮小時: 22px
最小: 20px
```

20px未満に縮小してはならない。

収まらない場合は、路線名の表示用短縮名をデータとして持つ。

例：

```text
東京メトロ副都心線
↓
副都心線
```

自動横スクロールやマーキー表示は禁止する。

## 右側

表示優先順位：

1. 種別＋行先
2. 方向
3. 列車特定中
4. 空欄

例：

```text
快急 新宿
特急 小田原
上り
列車特定中
```

右揃えとする。

文字サイズ：

```text
標準: 20px
最小: 18px
```

1行表示とし、折り返してはならない。

---

# 9. SPEED領域

座標：

```text
X: 24
Y: 50
Width: 528
Height: 110
```

現在速度を画面中央へ配置する。

表示構成：

```text
[速度数字] [km/h] [推定マーク]
```

例：

```text
108 km/h
103 km/h  ~
```

## 速度数字

```css
.speed-value {
  font-size: 104px;
  line-height: 1;
  font-weight: 700;
  letter-spacing: -2px;
}
```

速度は整数表示を基本とする。

```ts
displaySpeedKmh = Math.round(filteredSpeedKmh);
```

小数点以下は常用画面に表示しない。

表示範囲：

```text
0〜999 km/h
```

値が取得できない場合：

```text
-- km/h
```

`0`と`--`を明確に区別する。

## 単位

```css
.speed-unit {
  font-size: 24px;
  line-height: 1;
  font-weight: 600;
}
```

速度数字のベースライン付近へ配置する。

単位を速度数字と同じ大きさにしてはならない。

## 推定マーク

GPS観測値ではなく、デッドレコニングや補間値を表示している場合は、速度の横に固定位置で`~`を表示する。

```css
.speed-estimated {
  font-size: 28px;
  font-weight: 700;
}
```

推定マークを速度数字の文字列へ直接連結してはならない。

推定マークの有無で速度数字の中心位置が移動しないよう、専用の固定幅領域を確保する。

---

# 10. SEGMENT領域

座標：

```text
X: 24
Y: 168
Width: 528
Height: 70
```

SEGMENT領域は次の3段で構成する。

```text
前駅名                              次駅名
━━━━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━
区間MAX 115                    次まで 4.2km
```

## 駅名行

座標：

```ts
const STATION_ROW = {
  y: 168,
  height: 28,

  previous: {
    x: 24,
    width: 230,
  },

  next: {
    x: 322,
    width: 230,
  },
};
```

前駅は左揃え、次駅は右揃えとする。

次駅名は前駅名より高い輝度を使用してよい。

```text
前駅: Secondary
次駅: Primary
```

駅名文字サイズ：

```text
標準: 24px
縮小時: 22px
最小: 20px
```

20px未満へ縮小してはならない。

長い駅名は以下の順で対応する。

1. 24pxで表示
2. 22pxへ縮小
3. 20pxへ縮小
4. 表示用短縮名を使用
5. 末尾を省略

マーキー表示は禁止する。

駅名が未確定の場合：

```text
前駅不明
次駅推定中
```

または：

```text
---
---
```

不確実な駅名へ、小さな`?`を大量に付けない。

---

# 11. 区間進捗バー

座標：

```ts
const SEGMENT_PROGRESS = {
  x: 24,
  y: 202,
  width: 528,
  height: 6,
};
```

線の太さは6pxを基本とし、4px未満にしてはならない。

現在位置マーカー：

```text
Width: 12px
Height: 12px
```

マーカーは線の中央へ配置する。

進捗率：

```ts
progress =
  distanceFromPreviousStation /
  totalSegmentDistance;
```

値は`0.0〜1.0`へ制限する。

```ts
progress = Math.max(0, Math.min(1, progress));
```

区間特定の信頼度が低い場合は、進捗マーカーを表示しない。

その場合はバー全体をDisabled輝度で表示するか、バー自体を非表示にする。

GPS復帰時にマーカーを瞬間移動させず、表示上は数秒かけて補正する。

---

座標：

```ts
const SEGMENT_INFO_ROW = {
  y: 216,
  height: 22,

  left: {
    x: 24,
    width: 260,
  },

  right: {
    x: 292,
    width: 260,
  },

```

左側：

```text
区間MAX 115
```

または：

```text
区間平均 87
```

右側：

```text
次まで 4.2km
```

距離が1km未満の場合：

```text
次まで 620m
```

文字サイズ：

```text
18px
```

右側は右揃えとする。

速度が優先情報であるため、この行へ詳細なデバッグ値を表示してはならない。

# 13. FOOTER領域

座標：

```text
X: 24
Y: 244
Width: 528
Height: 28
```

左右2領域に分ける。

左側表示候補：

```text
上り 3004列車
下り 104M
上り / 列車特定中
座間 停車中
```

右側表示候補：

```text
GPS
GPS弱
DR 8s
補正中
測位中
```

文字サイズ：

```text
18px
```

右側は右揃えとする。

状態表示の位置は固定し、GPSからDRへ変わっても位置を動かさない。

# 14. 状態別表示

## 14.1 GPS良好

```text
速度: Primary
推定マーク: 非表示
Footer右: GPS
進捗バー: 表示
```

## 14.2 GPS精度低下

```text
速度: Primary
推定マーク: 状況により表示
Footer右: GPS弱
進捗バー: 継続表示
```

GPS位置ジャンプを直接画面へ反映してはならない。

## 14.3 デッドレコニング

```text
速度: Primary
推定マーク: 表示
Footer右: DR 8s
進捗バー: 推定位置で継続
```

速度数字そのものを暗くしすぎてはならない。

推定中であることは`~`とFooterで示す。

## 14.4 GPS再取得

```text
速度: Primary
推定マーク: 表示
Footer右: 補正中
```

GPS復帰直後に速度、駅名、進捗バーを同時にジャンプさせない。

## 14.5 低信頼（速度不明）

デッドレコニングの低信頼区間（GPS経過20〜45秒）は§14.3の表示を継続する。

コースティング予算（45秒）を超えて速度の推定を打ち切った後（GPS経過45〜60秒）:

```text
速度: --
推定マーク: 非表示
Footer右: 測位中
路線名・駅名・進捗バー: 維持
```

速度が出せないことと位置を見失ったこと（§14.6）は別の事象として扱う。

線路上の推定位置が生きている限り、路線・駅の表示は破棄しない。

状態遷移の詳細は `docs/GPS_LOSS_SPEED_STATE_SPEC.md` を参照。

## 14.6 位置喪失

```text
速度: -- km/h
推定マーク: 非表示
Header左: 路線再特定中
駅名: ---
進捗バー: 非表示
Footer右: 測位中
```

最後の速度を無期限に固定表示してはならない。

## 14.7 駅接近

レイアウトは変更しない。

次駅までの距離だけを強調する。

例：

```text
まもなく 座間
```

または：

```text
次まで 320m
```

点滅は禁止する。

## 14.8 停車中

レイアウトは維持する。

速度：

```text
0 km/h
```

駅到着後は、区間を次の区間へ切り替える。

例：

```text
座間                              相武台前
●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Footer左：

```text
座間 停車中
```

必要に応じて、直前区間の最高速度をSEGMENT補助情報へ数秒間表示してよい。

# 15. 情報の信頼度による表示制御

## 路線信頼度

```text
0.80以上:
正式路線名を表示

0.55〜0.79:
路線候補を表示し、Footerに推定を示す

0.55未満:
路線特定中
```

## 区間信頼度

```text
0.80以上:
駅名と進捗バーを表示

0.55〜0.79:
駅名を表示、進捗バーをDisabled表示

0.55未満:
駅名と進捗バーを非表示または推定中表示
```

## 列車信頼度

```text
0.85以上:
種別、行先、列車番号を表示

0.65〜0.84:
種別、行先を表示

0.65未満:
方向のみ表示、列車特定中
```

内部の信頼度数値を常用HUDへ直接表示しない。

# 16. 文字列短縮ルール

HUD用に、通常名称とは別の表示用名称を持てるようにする。

```ts
interface HudDisplayName {
  fullName: string;
  shortName?: string;
  veryShortName?: string;
}
```

例：

```ts
{
  fullName: "東京メトロ副都心線",
  shortName: "副都心線"
}
```

```ts
{
  fullName: "とうきょうスカイツリー",
  shortName: "スカイツリー"
}
```

縮小順序：

```text
標準名
↓
文字サイズを段階的に縮小
↓
shortName
↓
veryShortName
↓
末尾省略
```

文字サイズを先に極端に小さくするのではなく、意味が維持される短縮名を優先する。

---

# 17. 更新頻度

内部推定更新とHUD描画を分離する。

推奨値：

```ts
const HUD_UPDATE_CONFIG = {
  navigationPredictionIntervalMs: 100,
  progressUpdateIntervalMs: 500,
  speedRenderIntervalMs: 500,
  metadataRenderIntervalMs: 1000,
};
```

速度表示は最大2Hz程度とする。

内部推定値が高頻度で変化しても、毎フレーム描画してはならない。

速度表示更新条件：

```ts
const shouldUpdateSpeed =
  roundedSpeed !== previousRoundedSpeed ||
  now - lastSpeedRenderAt >= 1000;
```

次の表示は禁止する。

* 数字を滑らかにスクロールするアニメーション
* 毎フレーム数値を変える
* 点滅
* フェードイン／フェードアウトの連続使用
* 横方向へ流れる文字

路線名、列車情報、駅名は値が変わった時だけ更新する。

---

# 18. レイアウトの安定性

以下の変化で速度数字の中心位置を変えてはならない。

```text
9 → 10
99 → 100
GPS → DR
推定マークなし → あり
km/h表示あり → あり
```

各表示領域に固定幅を与えること。

状態表示の文字長が変わっても、右端基準で表示する。

駅名が長くなっても、進捗バーの位置を動かしてはならない。

---

# 19. 線とアイコン

線幅は2px以上とする。

区間進捗バーは4〜6pxとする。

複雑なピクトグラムを使用しない。

使用可能な記号例：

```text
●
~
→
GPS
DR
MAX
```

使用を避けるもの：

* 細かい地図
* 複雑な鉄道アイコン
* 小さなアンテナアイコン
* 小さな警告三角形
* 色の違いだけで意味を伝える表現

# 22. 視認性確認モード

デバッグ画面に、HUDの見づらさを模擬する確認モードを用意する。

最低限、以下を切り替えられるようにする。

```text
通常表示
輝度低下
コントラスト低下
軽いぼかし
背景が明るい状態
```

例：

```css
.hud-preview.optical-stress {
  filter: blur(0.7px) contrast(0.8);
  opacity: 0.85;
}
```

このモードで読めない18px文字がある場合、情報量または文字サイズを再調整する。

このフィルターは開発用プレビューだけで使用し、実機HUDには適用しない。

# 23. 実機テスト条件

以下の状況で確認する。

* 明るい屋外
* 暗い車内
* 窓の外が明るい状態
* 走行中に一瞬だけ見る
* 立った状態
* 座った状態
* 頭を少し動かした状態
* 速度が頻繁に変化する状態
* GPSからDRへ切り替わる状態
* 長い駅名が表示される状態

確認時は、画面を数秒凝視して読めるかではなく、約0.5〜1秒の視認で以下が分かるかを評価する。

```text
現在速度
次駅
走行区間

```

# 24. アクセプタンステスト

以下をすべて満たすこと。

## レイアウト

* HUDが576×288pxからはみ出さない
* 重要情報が安全領域内にある
* 18px未満の常用文字が存在しない
* 3桁速度でも単位と重ならない
* 推定マークの有無で速度位置が動かない
* GPS／DR切替でFooter位置が動かない
* 長い路線名や駅名で2行折り返しが発生しない

## 視認性

* 速度が最も大きく明るい
* 次駅名が速度に次いで認識しやすい
* 0km/hと測位不能が区別できる
* 推定速度であることが分かる
* 点滅や高速更新がない
* 光学ストレス確認モードでも速度と次駅が読める

## 状態表示

* GPS良好
* GPS弱
* デッドレコニング
* GPS再取得
* 位置喪失
* 駅接近
* 停車中
* 路線不明
* 列車不明

以上の各状態でレイアウトが崩れないこと。

## 実機

* 速度を0.5〜1秒程度で認識できる
* 走行区間を短い視線移動で認識できる
* DR移行時に表示が不自然に停止しない
* GPS復帰時に複数要素が同時に大きくジャンプしない
* 窓の外が明るい環境でも主要情報が識別できる

# 25. 実装順序

以下の順序で実装する。

1. 576×288px固定ルート
2. 安全領域
3. HEADER
4. SPEED
5. SEGMENT駅名
6. 区間進捗バー
7. SEGMENT補助情報
8. FOOTER
9. 輝度階層
10. 長い文字列の縮小・短縮

13. HUDテストデータ
14. 光学ストレス確認モード

追加情報が必要な場合は、まずPage 2へ配置すること。

Page 1へ情報を追加する場合は、既存の文字サイズを小さくするのではなく、表示項目の優先順位を再検討すること。
