# Phone UI 再構成（公開版に向けた画面整理）

日付: 2026-09-08
ブランチ: `control-phone-ui-redesign`

## 目的

Even App の WebView に表示されるスマートフォン側画面（Control Interface / Phone UI）を、公開版として
一般ユーザが見て分かる構成に整理する。

- トップは「ユーザ操作が必要なもの」と「シンプルな状態表示」だけにする。
- テスター向け診断記録と、推定状態の詳細（デバッグパネル）は全画面の詳細画面に移す。
- 乗車履歴を、現在の乗車状態と同じ優先度でトップに置く。ただし履歴の一覧・エクスポート機能そのものは
  別 Issue で設計・実装するため、本 spec ではカードの枠と空状態だけを用意する。

## 現状

`index.html` は 1 枚の縦長ページで、ヘッダー（5 ボタン）、576px 固定の HUD 実寸プレビュー、路線再検出、
テスター向け診断記録、デバッグパネル（7 カード）が上から順に並ぶ。スマホ幅では HUD プレビューが横スクロールになり、
候補路線ボタンにはセグメント ID と生スコアが出る。デバッグパネルはログ更新のたびに innerHTML を丸ごと再描画する。

## 制約

- 診断収集の状態は全画面で常時見える必要がある（`docs/TELEMETRY_AND_SENTRY.md`「スマートフォン画面下部に診断状態を常時表示する」）。
- `app.json` の entrypoint は `index.html` 1 つ。画面遷移はページ内で行い、各詳細画面に自前の「戻る」を置く。
  Even App WebView にネイティブの戻る操作がある証拠はないため、それに依存しない。
- iOS の DeviceMotion 許可はユーザのタップ起点でしか取得できない。モーションセンサー有効化はユーザ操作として残す。
- `docs/HUD_UI_UX_REQUIREMENTS.md` 21 章の「13 状態をワンタップで切り替える開発用 HUD プレビュー」は未実装。
  本 spec では実装しないが、推定状態の詳細画面にその置き場を確保する。
- テスターはヘッダーのビルド情報でパッケージ更新を確認している。全画面で見えるようにする。

## 画面構成

4 画面をハブ & スポーク構成で持つ。ホームから各詳細へ入り、詳細から「‹ 戻る」でホームに戻る。

| 画面 | ルート | 内容 |
| --- | --- | --- |
| ホーム | `#/` | 現在の乗車カード、路線再検出、乗車履歴カード、副次入口 2 行 |
| 乗車履歴 | `#/history` | 空状態のみ（別 Issue で一覧・エクスポートを実装） |
| テスター向け診断記録 | `#/diagnostics` | 現在の診断セクションをそのまま移設 |
| 推定状態の詳細 | `#/debug` | HUD 実寸プレビュー、GPS ソース切替、デモ、デバッグパネル 7 カード |

共通要素:

- ヘッダー: アプリ名とビルド情報。詳細画面ではアプリ名の左に「‹ 戻る」を出す。
- 診断状態チップ: 画面下部固定。全画面で表示し、タップで `#/diagnostics` へ移動する。
  表示内容とスタイル（有効 / 端末保存中 / 一時停止 / 停止、エラー色）は現在の `diagnostic-indicator` を維持する。

### ホーム

```
┌──────────────────────────┐
│ RailGlance        v0.1.3 │
├──────────────────────────┤
│ ⚠ モーションセンサーを有効化 [有効化] │  ← 未許可のときだけ出るバナー
├──────────────────────────┤
│ 小田急小田原線      上り  │  ← 現在の乗車カード 1 行目: 路線 + 方向
│ 93 km/h            GPS ● │  ← 2 行目: 速度 + 補足状態
└──────────────────────────┘
        [ 路線を再検出 ]      ← 候補があるときだけ下に候補リストを展開
┌──────────────────────────┐
│ 乗車履歴          すべて ›│  ← 乗車履歴カード（現在の乗車カードと同じ大きさ・階層）
│ 乗車履歴はまもなく        │
│ 利用できるようになります   │
└──────────────────────────┘
  テスター向け診断記録 ›       ← 副次入口。控えめな 1 行リンク
  推定状態の詳細 ›
┌──────────────────────────┐
│ 診断収集: 停止           │  ← 常時表示チップ（固定下部）
└──────────────────────────┘
```

**現在の乗車カード** は `HudViewModel` と `DatasetSyncStatus` だけから組み立てる。

| 行 | 左 | 右 | 元データ |
| --- | --- | --- | --- |
| 1 | 路線名 | 方向 | `header.lineName` / `header.serviceOrDirection` |
| 2 | 速度（`93 km/h`、推定中は `~93 km/h`） | 補足状態 | `speed.*` / `footer.statusRight` |

- 路線判定中・GPS 不良・位置喪失のときは、グラス側と同じく 1 行目に `header.lineName`（「路線判定中」など）が
  そのまま入り、速度は `--` になる。ホーム側で状態分岐を増やさない。
- 補足状態の表示は `statusMode` で色分けする: `GPS` は通常色、`GPS_DEGRADED` / `DR` / `REACQUIRING` / `UNCERTAIN` は
  注意色、`SPEED_UNKNOWN` / `LOST` は警告色。
- データセット同期が `downloading` / `error` / `unavailable` のときだけ、2 行目右に `· データ取得中` /
  `· データ取得エラー` を追記する。`bundled` / `cached` / `cloud` では何も出さない。

**路線再検出** はカードの直下に 1 ボタン。現在の挙動（`startManualReacquire` → 候補リスト表示 →
候補タップで `lockSelectedRoute` → 「自動判定に戻す」で `unlockManualRoute`、離脱警告）は維持する。
候補の表示は `路線名` と `約120m` の 2 要素に絞り、セグメント ID とスコアは出さない。同じ路線名の候補が
複数並ぶ場合だけ、区別のために `segment.id` を小さく添える。

**モーションセンサー有効化** は未許可のときだけバナーで出し、許可後は消す。現在の `alert()` による結果通知はやめ、
バナー内のテキストを差し替えて結果を伝える（許可されなかった場合はバナーを残し、理由を 1 行で表示する）。

**乗車履歴カード** は本 spec では見出し、「すべて ›」リンク、空状態テキストだけを持つ。カード内の中身は別 Issue が
差し替える前提で、`#history-card-body` のような 1 つの差し替え領域として作る。

### 乗車履歴（詳細）

「‹ 戻る」付きのヘッダーと空状態テキストだけ。一覧、詳細、エクスポートは別 Issue。
エクスポート手段（共有シート / クリップボード / ダウンロード）は WebView での可否が未確認のため、本 spec では決めない。

### テスター向け診断記録

現在の `diagnostic-section`（説明文、同意チェック、参加コード、開始 / 停止 / 削除、状態表示）を、
文言・挙動を変えずにこの画面へ移す。`buildDiagnosticPanelView` と `RuntimeTelemetryManager` の連携はそのまま。

### 推定状態の詳細

開発者・テスター向け。上から順に:

1. HUD 実寸プレビュー（576×288）。コンテナ幅に合わせて CSS `transform: scale()` で縮小し、横スクロールをなくす。
   将来の 13 状態切替ボタン列を置く領域をプレビューの直下に確保する（本 spec では空）。
2. 位置ソース: `実機GPS開始`（Browser Geolocation へ切替）、`停止`、`小田急線デモ`、`新幹線デモ`。現在の挙動のまま。
3. デバッグパネル 7 カード（`DebugPanel`）。

`DebugPanel` は画面が表示されているときだけ DOM を更新する。非表示中は最新の入力（ログエントリ、画像結果、同期状態、
ブリッジ診断）を保持しておき、表示に切り替わった時点で 1 回描画する。

## ナビゲーション

- `location.hash` をルートとして使う。未知の hash と空は `#/` に正規化する。
- `hashchange` で表示ビューを切り替える。各ビューは `<section data-view="…">` で、非表示のものは `hidden` にする。
- 「‹ 戻る」は `#/` へ遷移する（`history.back()` に依存しない）。
- 起動時のビューは常にホーム。`onLaunchSource` による分岐は今回は行わない。

## 実装構成

既存の「純粋関数でビューモデルを作り、`main.ts` で DOM に流し込む」パターンに合わせる。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 4 つの `<section data-view>` と共通ヘッダー・診断チップに再構成 |
| `src/index.css` | カード・副次入口・バナー・戻るボタン・スケール付きプレビューのスタイルを追加。デバッグ系スタイルは維持 |
| `src/ui/router.ts` | `parseRoute(hash): ViewName` と `applyRoute(document, view)`。純粋関数部分をテスト対象にする |
| `src/ui/home-status-card.ts` | `buildHomeStatusView(model: HudViewModel, sync?: DatasetSyncStatus): HomeStatusView` |
| `src/ui/route-candidates.ts` | `buildRouteCandidateItems(match: RouteMatch \| null, tieMargin): RouteCandidateItem[]` と表示可否判定（`main.ts` から移す） |
| `src/ui/motion-banner.ts` | `buildMotionBannerView(status): MotionBannerView`（表示可否と文言） |
| `src/ui/debug-panel.ts` | 表示中フラグと保留描画を追加 |
| `src/main.ts` | ルーター初期化、各ビルダーの結果を DOM に反映、イベント配線 |

`src/ui/diagnostic-panel.ts` は変更しない。

## テスト

- `tests/ui/router.test.ts`: hash の正規化、未知ルートのホーム fallback。
- `tests/ui/home-status-card.test.ts`: 通常 / 推定中 / 判定中 / LOST の各 `HudViewModel` と同期状態の組み合わせで
  2 行の文言と状態クラスを検証。
- `tests/ui/route-candidates.test.ts`: 候補表示の可否条件（`REACQUIRING` / `UNRESOLVED` / 拮抗）、ラベル整形、
  同名路線での ID 付与。
- `tests/ui/motion-banner.test.ts`: 許可状態ごとの表示可否と文言。
- `tests/ui/debug-panel.test.ts`: 非表示中は DOM を更新せず、表示切替時に最新入力で 1 回描画する。
- 手動確認: `pnpm dev` の公式シミュレーターと実機 Even App で、4 画面の遷移、診断チップの常時表示、
  HUD プレビューの縮小表示、路線再検出の候補展開を確認する。

## スコープ外

- 乗車履歴の記録・一覧・エクスポート（別 Issue）。
- HUD プレビューの 13 状態切替（`HUD_UI_UX_REQUIREMENTS.md` 21 章）。
- `onLaunchSource` に応じた初期画面の切替。
- 英語ローカライズ（`app.json` は `ja` / `en` を宣言しているが、現在の UI は日本語のみ。本 spec も日本語のまま）。
